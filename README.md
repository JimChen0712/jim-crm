# Etalking CRM 增強面板

Etalking CRM 是運行在 Etalking 後台的書籤工具，用來整合名單管理、Google Sheets 同步、聯繫歷史、觸及率計算與自動撥號。

原始碼位於 `src/`，建置後產生 `dist/crm.js` 與專案根目錄的 `crm.js`。正式書籤會載入 GitHub `main` 分支上的 `crm.js`。

## 主要功能

### 名單管理

- 顯示新單、常態名單、Demo 名單與釋出名單。
- 支援業務、來源、類型、姓名與電話篩選。
- 可在面板內設定 A/C 評級、備註、再次留單與釋出名單。
- 名單姓名旁可單筆撥號，或點擊歷史圖示查看完整系統紀錄。
- 聯繫歷史只在點擊後載入，不會預先抓取數千筆舊名單。

### 名單追蹤與觸及率

- **新單 (Type 1)**：使用 3 天 6 次的追蹤進度。
- **常態名單 (Type 2)**：依持有天數與聯絡次數計算觸及率。
- 前 3 天目標為 6 次；第 4 天起，每天增加 1.5 次目標。
- 目標次數：`6 + ceil((持有天數 - 3) * 1.5)`。
- 觸及率：`聯絡次數 / 目標次數 * 100%`。
- 已有實質聯繫或預約 Demo 時，常態觸及率依現行規則停止計算。

### Google Sheets 同步

- **工作表1**：儲存新單、再次留單、評級、備註與觸及率。
- **Demo名單總表**：儲存 Demo 名單、進單日期與轉 Demo 日期。
- 「同步名單細節」會抓取新單與常態名單的後台軌跡。
- 「同步常態單觸及率」只寫入有變化的資料，單筆失敗會自動重試，並不會中斷後續名單。
- 「同步 Demo」會補抓 Demo 軌跡並寫入 Demo 總表。

## 資料語意

工作表1主要欄位：

```text
member_id, 姓名, 電話, 來源, 業務, uid,
進單日期, 進單月份, 目前狀態, 等級(A/C),
備註, 最後更新, 名單觸及率
```

- 「再次留單」代表舊名單重新從官網填單，邏輯上視同新單，但狀態欄寫入「再次留單」。
- 常態名單若只用來儲存等級或備註，狀態欄保持空白，不會混成新單。
- 尚未存在工作表1的舊常態名單，不會因觸及率同步而自動建立新列。

## 自動撥號

### 撥號建立

1. 先顯示「正在建立撥號」，並同時載入該名單的歷史紀錄。
2. 撥號 API 成功接受請求後，才開始 35 秒倒數。
3. API 失敗、逾時或回傳明確錯誤時，不倒數、不自動寫入未接，並提供重新撥號。
4. 分機號碼依 `crmUid` 儲存在本機，第一次輸入後可在撥號面板修改。

### 連續撥打與紀錄

- 第一次未接：寫入 `未接 *1`，確認寫入成功後自動再撥一次。
- 第二次未接：寫入 `未接 *2`，確認寫入成功後切換下一位。
- 「語音／下一通」：寫入 `語音 *1` 或 `語音 *2`，並直接切換下一位，不會重複撥打當前名單。
- 手動按未接或語音時，會要求確認實體話機已掛斷、線路已清空。
- 自動未接、語音與已接聽紀錄的下次聯繫日期預設為當天往後 10 天。連續兩筆會寫入同一個十天後日期，不會累加成 20 天。

### 撥號寫入保護

自動未接、語音與已接聽紀錄在寫入前會：

1. 檢查面板是否已開啟超過 2 小時。
2. 檢查後台 session 是否仍有效。
3. 檢查 GitHub `main` 是否已有新版 `crm.js`。
4. 送出紀錄後回讀該名單歷史，確認相同內容的紀錄數已增加。

若無法確認寫入成功，自動撥號會停留在當前名單，不會繼續第二次撥號或切換下一位，避免漏寫。

## 安全與限制

- 只允許在 Etalking 指定後台網域執行。
- 面板開啟超過 2 小時後禁止新的寫入。
- 寫入前會檢查後台登入狀態與正式版本。
- GAS 請求有 timeout 與明確錯誤提示。
- 撥號 API 成功只能代表後端接受撥號請求；若後端沒有提供 ringing 或 call status，前端無法完全確認實體電話是否已響鈴。
- 目前為書籤工具，不適合跨頁長時間續跑。若未來需要一鍵跨頁流程，建議改為 Chrome extension。

## 專案結構

```text
src/main.js      CRM 主邏輯、UI、同步、歷史與撥號
src/api.js       Google Apps Script API 通訊
src/config.js    GAS URL、MANAGER_UID、USER_DICT 與其他設定
crm.js           正式書籤載入的 build 產物
dist/crm.js      Vite build 產物
vite.config.js   建置與 build ID 設定
```

## 開發與建置

需求：Node.js 與 npm。

```bash
npm ci
npm run build
```

`npm run build` 會執行 Vite，並將 `dist/crm.js` 複製到專案根目錄的 `crm.js`。每次 build 都會產生新的 build ID，因此兩份產物必須一起 commit。

## 發布流程

1. 修改 `src/*`。
2. 執行 `npm run build`。
3. 確認 `crm.js` 與 `dist/crm.js` 內容一致。
4. Commit `src/*`、`crm.js` 與 `dist/crm.js`。
5. Push 到 GitHub `main`。
6. 重新整理 Etalking 後台，重新點擊書籤測試。

## 上線前檢查

- 一般壓紀錄、評級與備註寫入正常。
- 第一次未接寫入後才進行第二次撥號。
- 第二次未接寫入後才切換下一位。
- 語音／下一通不會重複撥打當前名單。
- API 失敗時不倒數、不自動壓未接。
- 同步常態單觸及率只寫入異動資料，並正確回報成功、無變化與失敗數。
- Demo 同步能正確取得進單日期與轉 Demo 日期。
